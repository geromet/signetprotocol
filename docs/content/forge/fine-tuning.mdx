# Learning and fine-tuning

<Callout type="warning">Draft proposal, part of Signet 2.</Callout>

## The Signet Forge cycle

```mermaid
flowchart LR
  S["Suggest<br/>the model scores"] --> R["Review<br/>a person picks"]
  R --> P["Pin<br/>goes to the profile"]
  P --> L["Learn<br/>training examples"]
  L --> F["Fine-tune<br/>a better model"]
  F --> S
```

The fine-tuned model suggests better next time.

Every approved decision is **eligible** to become an example: *situation, options, chosen*. With enough examples the model can be fine-tuned for video games. With a model like CLM, which separates a large frozen encoder from two small "heads", only those heads would need training, which should be cheap. This has not been tested yet.

**Review-branch proposal.** Local approval is not consent to contribute. Contribution to a shared dataset is a separate explicit action under the dataset contribution terms: `LOCAL_APPROVAL != DATASET_CONTRIBUTION`. Dataset examples should carry immutable identity, provenance, semantic/profile version, license and invalidation lineage. See [Translator trust and validation](/proposals/translator-trust-and-validation/).

## Data rules

- Only names and identifiers. **Never** game files: no textures, sounds or models.
- Nothing about the player: no usernames and no key logs.
- Contributed under an open license, as a separate explicit opt-in, so the whole community benefits.

## Validate before relying on it

Before a model becomes part of Forge, we will run a small experiment: about 30 cases, comparing hand-written rules, plain text similarity and a contrastive ranker. We will measure top-1 accuracy and how often a person overrides the suggestion. The result decides whether a model adds value.
