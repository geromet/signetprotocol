# Reliability and limits

<Callout type="warning">Draft proposal, part of Signet 2.</Callout>

## Why this makes the protocol more reliable

- **The server does not change for each new game.** It only understands intents and archetypes.
- **Nothing is random during the match.** Every decision comes from a pinned profile.
- **AI stays outside the protocol.** If a model fails or changes, the match is not affected.
- **Limited games do not break the match.** Thanks to capabilities, the server knows what each one can do.
- **Building a translator is easier.** Calibration solves the obvious, the model suggests the hard parts and Forge keeps the work.

## Limits and rules

- **Legal.** Calibration only reads the player's own devices and what the game officially allows: open-source engines, permitted mods or your own server. No code is injected into online games and no anti-cheat systems are bypassed. A closed game with no legitimate way to read or drive it is out of scope.
- **Physics.** Intents do not remove the need for a common physics on the server. The motion profile helps each game feel faithful, but the server remains the authority.
- **Model not validated.** We have not tested any model for this yet. The figures for the model mentioned are its authors', on other tasks.

## Compatibility with the current version

Signet/1 already contains the seed of this: its `Intencion` message carries forward, strafe, turn, run, fire, use and weapon, and the weapons `ARMA_PUNO`, `ARMA_PISTOLA` and `ARMA_ESCOPETA` are already archetypes that each viewer draws its own way. Signet/1 only grows with optional fields, so the first steps (capabilities in the greeting and archetype identifiers) can be added without breaking anything. The full English vocabulary and any renaming are left for Signet/2. See [versioning](/protocol/versioning/).
