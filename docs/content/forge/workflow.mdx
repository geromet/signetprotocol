# Translation profiles: decisions that do not change

<Callout type="warning">Draft proposal, part of Signet 2.</Callout>

Every decision is saved in a file next to the translator's `signet.json`, similar to the lock files that package managers use. Once pinned, the decision is **deterministic within that profile revision**: it always gives the same result. Pinned is not the same as current: compatibility can become `SUSPECT` or `INVALID` when declared dependencies change. See [Translator trust and validation](/proposals/translator-trust-and-validation/).

```json
{
  "key": "archetype:weapon.ranged",
  "choice": "minecraft:bow",
  "source": "human",
  "candidates": [["minecraft:bow", 0.81], ["minecraft:crossbow", 0.74], ["minecraft:fishing_rod", 0.22]],
  "resolver": "clm-v0.1-8b",
  "pinned": true
}
```

## What happens with something that is not in the profile?

| Policy | Behavior | For whom |
|---|---|---|
| **Strict** | It is ignored. Nothing happens | Tournaments, serious servers |
| **Suggest** | The model's best option is used, marked as provisional, and queued for review in Forge | Casual matches |
| **Ask** | It is decided on the spot with Forge | Whoever is building the translator |

<Callout type="warning">
**Safety rule:** intents that affect the simulation (moving, firing) must **always** come from a pinned decision. Otherwise client prediction and the server would drift apart. Appearance is local to each player, so it can stay provisional without affecting anyone else.
</Callout>

## Authority and ownership (review-branch proposal)

Not every entry has the same owner or override rule. We propose an explicit **authority class** per entry:

| Class | Natural authority |
|---|---|
| `INPUT_BINDING` | participant / adapter |
| `MOTION_OBSERVATION` | measured adapter evidence |
| `SEMANTIC_MAPPING` | translator / profile publisher |
| `APPEARANCE_MAPPING` | participant / client |
| `SESSION_POLICY` | server / session |

Precedence is applied per class. There is not one universal "player pin wins" rule for simulation-affecting semantics.

The effective profile is derived, not merged by popularity:

```text
publisher baseline (immutable, versioned)
+ participant overlay (local, owned by the player)
+ session-compatible derivation
= effective profile
```

A package update must not silently rewrite player-owned pins. See [Semantic contracts](/proposals/semantic-contracts/).

## The review queue

Provisional choices made during real matches land in Forge's **review queue**. A person sees the candidates and their scores, picks one and pins it. The next release of the profile carries the decision to every player.

Because the profile is a text file in the repository, the community can improve any translator with a pull request.
